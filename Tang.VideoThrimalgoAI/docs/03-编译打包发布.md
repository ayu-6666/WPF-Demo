# 编译打包发布

从干净环境到可交付安装包的完整流程。本文所有命令与体积均为本机实际执行结果（Windows x64、.NET SDK 10.0.401、`IpanelWpf.sln` 下的 `Tang.VideoThrimalgoAI` 模块）。

## 1. 前置条件

| 项 | 要求 / 本机实测 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| .NET SDK | 6.0 及以上；本机 10.0.401，可正常编译 `net6.0-windows` |
| 目标机运行时 | 框架依赖包需 **.NET 6 Desktop Runtime (x64)**；自包含包无需安装 |
| ffmpeg | 视频功能必需，本机位于 `D:\tang\software\ffmpeg\bin`（程序按“已保存配置 → 默认目录 → PATH → 常见位置”查找，见 `02-开发与环境部署.md`） |
| 磁盘 | 中间产物约 0.5 GB，建议预留 2 GB |

先确认工具链可用：

```powershell
dotnet --version
dotnet --list-sdks
D:\tang\software\ffmpeg\bin\ffmpeg.exe -version
```

## 2. 还原、编译

以下命令在 `d:\tang\vs-workspace\WPF-Demo\Tang.VideoThrimalgoAI` 目录下执行（也可替换为 `.csproj` 绝对路径）。

### 2.1 还原依赖

```powershell
dotnet restore Tang.VideoThrimalgoAI.csproj
```

实测输出（依赖已在本地缓存时）：

```
所有项目均是最新的，无法还原。
```

伴随两条已知警告（不影响结果，详见第 9 节）：

```
warning NU1603: ... 没有找到 OpenCvSharp4 4.8.1.26。已改为解析 OpenCvSharp4 4.9.0.20240103。
warning NU1603: ... 没有找到 OpenCvSharp4.runtime.win 4.8.1.26。已改为解析 OpenCvSharp4.runtime.win 4.9.0.20240103。
warning NU1900: 获取包漏洞数据时出错: Access to the path '...vuln_index.dat-new' is denied.
```

模型不走 NuGet，随构建从 `Models\` 复制（见第 4 节）。全新机器若 `Models\RealESRGAN_x4plus.onnx` 不存在，需按第 4 节先放置模型，否则包内会缺模型并回退纯算法。

### 2.2 Debug 编译

```powershell
dotnet build Tang.VideoThrimalgoAI.csproj -c Debug --nologo
```

产物：`bin\Debug\net6.0-windows\Tang.VideoThrimalgoAI.exe`，同目录 `Models\RealESRGAN_x4plus.onnx`（67,051,973 字节）。

### 2.3 Release 编译

```powershell
dotnet build Tang.VideoThrimalgoAI.csproj -c Release --nologo
```

产物：`bin\Release\net6.0-windows\`。指定 RID 发布后还会生成 `bin\Release\net6.0-windows\win-x64\`。

> 用 Visual Studio 时等价操作：打开 `IpanelWpf.sln`，右键项目 → 重新生成；配置选 `Debug` 或 `Release`，平台 `Any CPU`。

## 3. 发布（publish）

### 3.1 推荐：指定 win-x64 的目录发布

```powershell
dotnet publish Tang.VideoThrimalgoAI.csproj -c Release -r win-x64 --self-contained false -o C:\Temp\Tang_doc_pub
```

实测结果（本次验证）：

| 项 | 结果 |
|---|---|
| 退出码 | `0` |
| 文件数 | 21 |
| 目录体积 | 171 MB（按 1 MB = 1024×1024 字节统计） |
| 启动验证 | `Start-Process Tang.VideoThrimalgoAI.exe` 后进程存活，`MainWindowTitle = Tang.VideoThrimalgoAI` |
| 压缩包 | `Compress-Archive` 后 **100.9 MB**，21 个条目，含 `Models\RealESRGAN_x4plus.onnx` |

`--self-contained false` 表示框架依赖：目标机需装 .NET 6 Desktop Runtime，但换来体积与升级便利。

### 3.2 不指定 RID 的发布（不推荐直接交付）

```powershell
dotnet publish Tang.VideoThrimalgoAI.csproj -c Release -o C:\Temp\Tang_pub_verify
```

实测为 **58 个文件 / 445.5 MB**，且产物中出现 `runtimes\win-x64`、`win-x86`、`win-arm64`、`linux-x64`、`linux-arm64`、`osx-x64`、`osx-arm64`、`android`、`ios` 等目录。原因：未指定 RID 时 NuGet 会把包内**所有平台**的原生资产一起复制（`OpenCvSharpExtern.dll` 同时存在 x64 62,431,232 字节与 x86 42,479,104 字节两份），体积成倍增加且绝大多数是目标机用不到的文件。**交付包必须指定 `-r win-x64`。**

### 3.3 单文件发布（本机未验证通过，不建议）

```powershell
dotnet publish Tang.VideoThrimalgoAI.csproj -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o C:\Temp\Tang_pub_single
```

.NET 6 下单一文件必须自包含。本机执行失败，报错原文：

```
Access to the path 'D:\tang\donet_librarys\global_package\microsoft.aspnetcore.app.runtime.win-x64\6.0.36' is denied
```

原因是本机 NuGet 全局包目录（`D:\tang\donet_librarys\global_package`）中的运行时包缓存目录无写权限，与项目配置无关。若确需单文件：

1. 修复该目录 ACL，或把 `NUGET_PACKAGES` 指向可写目录后重试；
2. 单文件运行时会把原生 DLL 解压到临时目录，首启较慢，且 OpenCvSharp/ORT 原生库解压失败时排查困难。

**结论：本项目采用目录发布（zip 分发）。** 目录结构中的 `Models\` 与原生 DLL 一目了然，便于替换模型、核对哈希。

### 3.4 模型与 ORT 原生库的复制方式（实际机制）

不是 publish 参数，而是 `Tang.VideoThrimalgoAI.csproj` 中的复制规则 + NuGet 包自带原生资产：

```xml
<ItemGroup>
  <None Update="Models\RealESRGAN_x4plus.onnx" CopyToOutputDirectory="PreserveNewest" />
  <None Update="Models\NOTICE.txt" CopyToOutputDirectory="PreserveNewest" />
</ItemGroup>
```

`PreserveNewest` 保证源文件更新后重新复制，publish 与 build 共用同一规则。ORT 原生库由 `Microsoft.ML.OnnxRuntime` 包的 `runtimes\win-x64\native\` 资产在指定 RID 时自动落盘，无需手写拷贝。

### 5.2 命名建议

```
Tang.VideoThrimalgoAI-<版本号>-win-x64-portable.zip
例：Tang.VideoThrimalgoAI-1.0.0-win-x64-portable.zip
```

- 带上版本号与 `win-x64`、`portable`（框架依赖）标识，便于区分自包含包。
- 交付 zip 解压即用，不要在 zip 内再套一层同名目录（`build_all.bat` 用 `Compress-Archive -Path '<模块目录>\*'`，已满足）。
- 随包保留 `Models\NOTICE.txt`，满足 BSD-3-Clause 的分发声明要求。

### 5.3 一键批量打包（`build_all.bat`）

仓库根目录的 `build_all.bat` 同时处理 18 个模块，与本模块相关的实际行为：

| 行为 | 说明 |
|---|---|
| 用法 | `build_all.bat [Release\|Debug]`，默认 `Release` |
| 构建工具 | 优先 VS `vswhere` 定位 MSBuild，否则回退 `dotnet build` |
| 输出 | 每个模块编译后 `xcopy` 到 `Publish\<模块>\`，压缩为 `Publish\<模块>-<时间戳>.zip` |
| 清理 | 最后一个 zip 生成后删除模块目录，并对 `Publish` 根做安全清扫，**只保留 `.zip` 与 `logs\`** |
| 日志 | `Publish\logs\<模块>.log` |
| 中断保护 | 先清空 `Publish` 目录再开始，因此不要把待交付包直接放在 `Publish` 根 |

注意：该脚本走的是 `dotnet build`/MSBuild 默认输出（`bin\<CONFIG>\net*`），**不带 RID**，包内会同时含 x86/x64 原生库，体积偏大。要得到第 5.1 节的精简包，请单独执行 3.1 的 `publish` 命令。

## 6. 发布前检查清单

| # | 检查项 | 判定方式 |
|---|---|---|
| 1 | ffmpeg / ffprobe 可用 | 启动程序后视频页引擎状态显示版本行；或直接 `ffmpeg.exe -version` |
| 2 | 模型完整 | 大小 `67051973`、SHA-256 与第 4 节一致；界面超分状态显示“可用” |
| 3 | 模型缺失回退 | 临时改名 `Models\RealESRGAN_x4plus.onnx` 后修复一张图，状态提示应回退“纯算法”而非崩溃 |
| 4 | 批量默认值 | 图像页批量修复可选中文件夹、显示进度、失败项有汇总 |
| 5 | 超分默认值 | 超分默认关闭；开启后 >4MP 图按回退策略处理（不报错） |
| 6 | 语言切换 | 点击语言按钮，页签与视频页文案中英文即时切换，图像页正文保持中文（已知范围） |
| 7 | 图标与版本号 | **当前 `csproj` 未配置 `ApplicationIcon` 与 `Version`，发布前需补齐**（见下） |
| 8 | 输出不得等于输入 | 视频页把输出目录选成素材目录、文件名冲突时应被拦截并提示 |
| 9 | 对话框可显示 | 文件夹选择框能正常弹出（依赖 `EnableVisualStyles`） |
| 10 | 包内无调试残留 | 可删 `.pdb`；确认没有 `bin`/`obj`/临时目录混入 zip |

版本与图标当前为默认值（`1.0.0.0`，无自定义图标）。若要交付带版本信息的包，在 `csproj` 的 `PropertyGroup` 中补充：

```xml
<ApplicationIcon>Assets\app.ico</ApplicationIcon>
<Version>1.0.0</Version>
<FileVersion>1.0.0.0</FileVersion>
<Product>Tang.VideoThrimalgoAI</Product>
```

（本模块目前没有 `Assets\app.ico`，需先准备图标文件；本文不代为实现，属发布侧配置。）

## 7. 临时文件与中间产物约定

| 类型 | 位置 | 约定 |
|---|---|---|
| 编译中间产物 | `Tang.VideoThrimalgoAI\bin\`、`obj\` | 保留在本模块内，随 `dotnet clean` 清理 |
| 发布验证目录 | 系统临时目录，如 `%TEMP%\TANG_doc_pub` | **不要建在仓库内**；验证完成后立即删除 |
| 批量打包产物 | `Publish\` | 只保留 `<模块>-<时间戳>.zip` 与 `logs\`，脚本会自动清扫其他内容 |
| 运行时配置 | `%LocalAppData%\Tang.VideoThrimalgoAI\settings.json` | 保存 ffmpeg 路径，不随包分发 |
| 视频预览缩略图 | `%LocalAppData%\Tang.VideoThrimalgoAI\preview` | 可随时删除，程序会重建 |
| 崩溃日志 | `%TEMP%\TangVideoCrash.log` | 由 `App` 的未处理异常钩子写入，排障用 |

清理示例（只清本模块，不触碰其他模块产物）：

```powershell
Remove-Item -LiteralPath '.\bin','.\obj' -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath "$env:TEMP\TANG_doc_pub","$env:TEMP\TANG_doc_pub.zip" -Recurse -Force -ErrorAction SilentlyContinue
```

## 9. 常见故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 超分状态显示“不可用”，输出仍能生成 | 模型缺失/大小或哈希不符，服务按设计回退纯算法 | 按第 4 节核对文件与哈希；确认 `TANG_SR_MODEL_DIR` 未指向错误目录 |
| `warning NU1603`：`OpenCvSharp4 4.8.1.26` 被替换 | 该版本号在源上不可用，还原解析到 `4.9.0.20240103` | 可把 `csproj` 版本改为实际解析值消除警告；不改也不影响运行 |
| `warning NETSDK1138`：目标框架不受支持 | `net6.0-windows` 已 EOL | 属预期提示；如需长期维护，升级到 `net8.0-windows`（需回归 OpenCvSharp/ORT 版本） |
| 文件夹选择对话框不弹出 | 纯 WPF 消息循环下 WinForms 对话框缺少视觉样式 | 确认 `App.OnStartup` 调用 `Application.EnableVisualStyles()`，不要删除 |
| 提示“输出文件不能与输入视频相同” | 防覆盖保护（`EnsureOutputIsDistinct`） | 换输出目录或改输出文件名，不要指向源素材 |
| 视频功能报“未找到 ffmpeg” | 路径未保存且默认/PATH/常见位置都没有 | 在视频页重新指定 `ffmpeg.exe` 路径；或放到 `D:\tang\software\ffmpeg\bin` |
| ffmpeg 报“No such file”但路径已选 | 选择的是目录而非 `ffmpeg.exe`，或 `ffprobe.exe` 不在同目录 | 选 `ffmpeg.exe` 本身，并保证同目录有 `ffprobe.exe` |
| 发布包在目标机双击无反应 | 框架依赖包缺 .NET 6 Desktop Runtime | 安装运行时，或改自包含发布（体积显著增大） |
| 包体异常大（400 MB+） | 发布未指定 RID，带上了 x86 与 x64 两套原生库 | 重新用 `-r win-x64` 发布 |
| 单文件发布报 `Access ... is denied` | NuGet 全局包目录权限 | 修复 ACL 或改 `NUGET_PACKAGES` 指向可写目录；本项目建议直接用目录发布 |

排障优先看两处：`Publish\logs\<模块>.log`（构建期）、`%TEMP%\TangVideoCrash.log`（运行期未处理异常）。
