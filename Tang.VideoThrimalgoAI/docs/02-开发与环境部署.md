# 开发与环境部署

面向开发者，说明 Tang.VideoThrimalgoAI 的技术栈、目录结构、环境依赖、模型部署与本地调试方式。

## 1. 技术栈与实际版本

版本取自 `Tang.VideoThrimalgoAI.csproj`，均为实际引用（非推测）。

| 组件 | 版本 / 说明 |
|---|---|
| 目标框架 | `net6.0-windows`（.NET 6，WPF） |
| 语言 | C#，`LangVersion=latest`，`Nullable=enable` |
| UI 框架 | WPF + MaterialDesignThemes（暗色卡片/按钮/页签样式） |
| MVVM | CommunityToolkit.Mvvm 8.2.2 |
| 图像处理 | OpenCvSharp4 4.8.1.26 + OpenCvSharp4.runtime.win 4.8.1.26（还原时因版本不可用解析到 4.9.0.20240103，见 NU1603） |
| ONNX 推理 | Microsoft.ML.OnnxRuntime 1.17.1（CPU，本地执行） |
| 位图 | System.Drawing.Common 8.0.0 |
| 文件夹选择 | WinForms `FolderBrowserDialog`（`UseWindowsForms=true`，需 `EnableVisualStyles`） |
| 视频处理 | 外部本地 ffmpeg/ffprobe（非 NuGet 依赖） |

本项目为解决方案 `IpanelWpf.sln` 中的一个模块，打包脚本 `build_all.bat` 会连同其他模块一起构建。

## 3. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10/11 x64 |
| .NET SDK | 6.0 及以上；本机实测 10.0.401 可编译 `net6.0-windows`（会提示 NETSDK1138 EOL 警告） |
| 运行环境 | 框架依赖发布需安装 **.NET 6 Desktop Runtime (x64)**；也可自包含发布 |
| Visual Studio | 2022/2025，勾选“.NET 桌面开发”工作负载（含 WPF/WinForms） |
| ffmpeg | 本机路径 `D:\tang\software\ffmpeg\bin`，需同时存在 `ffmpeg.exe` 与 `ffprobe.exe` |
| 显示 | 建议 1440×900 以上（窗口默认 1500×920，最小 1000×680） |

### 3.1 ffmpeg 查找顺序

实现位于 `Services\FfmpegLocator.cs`，顺序如下：

1. 已保存配置：`%LocalAppData%\Tang.VideoThrimalgoAI\settings.json` 的 `FfmpegPath`；
2. 本机默认目录：`D:\tang\software\ffmpeg\bin\ffmpeg.exe`；
3. 系统 `PATH` 中各目录下的 `ffmpeg.exe`；
4. 常见位置：`C:\ffmpeg\bin`、`C:\ffmpeg`、`C:\Program Files\ffmpeg\bin`、`%USERPROFILE%\scoop\shims`、`%USERPROFILE%\scoop\apps\ffmpeg\current\bin`、`C:\ProgramData\chocolatey\bin`。

找到 ffmpeg 后，要求同目录存在 `ffprobe.exe`；否则界面提示“同目录缺少 ffprobe.exe”。界面“浏览”可手动指定并写回 `settings.json`。

## 4. ONNX 超分模型部署

| 项 | 值 |
|---|---|
| 文件名 | `Models\RealESRGAN_x4plus.onnx` |
| 大小 | 67,051,973 字节（约 63.95MB） |
| SHA-256 | `39d5218cfcef542d667821a0d2072cfa51bfd857ab0e4ae7dc067c399a88d323` |
| 模型结构 | RRDBNet，4 倍放大，ONNX opset 14，动态 H/W |
| 输入/输出 | `input` / `output`，NCHW RGB，取值 [0,1] |
| 上游/许可 | https://github.com/xinntao/Real-ESRGAN ，BSD-3-Clause |
| 运行时 | Microsoft.ML.OnnxRuntime CPU，仅读取本地文件，不发网络请求 |

部署规则：

- 模型放在模块 `Models\`，`csproj` 通过 `None Update ... CopyToOutputDirectory="PreserveNewest"` 复制到输出目录的 `Models\`；
- 仓库根 `.gitignore` 已排除 `Tang.VideoThrimalgoAI/Models/*.onnx`，模型不进源码控制；
- 运行时目录解析：环境变量 `TANG_SR_MODEL_DIR` 优先，否则 `AppContext.BaseDirectory\Models`；
- 启动/切换模型/勾选 2x 时会做“文件大小 + SHA-256”校验，失败则在界面显示“超分模型不可用：{原因}（将回退纯算法）”；
- 输入超过 4,000,000 像素、会话加载失败或推理异常时自动回退纯算法，状态栏标注“→ 纯算法回退”；
- 分块参数：`TileSize=320`、`TileOverlap=32`，输出按块羽化融合；线程数为 CPU 逻辑核数。

首次获取模型的方式见 `docs/03-编译打包发布.md`（随包分发或手动导入 `Models\`）。

## 5. 首次运行配置

1. 编译并运行程序；
2. 若视频页提示“未检测到 ffmpeg.exe”，点“浏览”选择 `D:\tang\software\ffmpeg\bin\ffmpeg.exe`；配置写入 `%LocalAppData%\Tang.VideoThrimalgoAI\settings.json`；
3. 图像页点“输出目录”、视频页点“输出目录”选择保存位置（默认分别为系统“图片”“视频”文件夹）；
4. 需要 AI 超分时确认 `Models\RealESRGAN_x4plus.onnx` 存在，界面状态行显示“可用”。

运行期产生的临时文件：`%LocalAppData%\Tang.VideoThrimalgoAI\preview\thumb_*.png`（视频首帧缩略图，加载后删除上一张）。

## 6. 依赖还原、编译与调试

```powershell
# 还原
dotnet restore .\Tang.VideoThrimalgoAI\Tang.VideoThrimalgoAI.csproj

# Debug 编译（输出 bin\Debug\net6.0-windows，含 Models\）
dotnet build .\Tang.VideoThrimalgoAI\Tang.VideoThrimalgoAI.csproj -c Debug

# Release 编译
dotnet build .\Tang.VideoThrimalgoAI\Tang.VideoThrimalgoAI.csproj -c Release

# 启动（也可直接 F5）
.\Tang.VideoThrimalgoAI\bin\Debug\net6.0-windows\Tang.VideoThrimalgoAI.exe
```

调试要点：

- 带视频参数启动：`Tang.VideoThrimalgoAI.exe "D:\video.mp4"`，视频页加载后会自动载入 `args[1]`；
- 图像处理链路：`MainViewModel.ProcessImageAsync`（模式分派）→ `ImageEnhancementService` / `SuperResolutionService` / 其他服务；批量走 `BatchProcessingService.ProcessFolderAsync`；
- 视频处理链路：`VideoProcessingViewModel` 组装参数 → `VideoJobService` 组装 ffmpeg 命令 → `FfmpegRunner` 执行并回报进度；
- 诊断入口主要是界面状态栏/弹窗（ffmpeg 的 stderr 会被捕获进异常消息）；
- 建议在 `VideoJobService` 的 `_runner.RunAsync` 与 `SuperResolutionService.Upscale` 处下断点复现参数与回退分支。

### 6.1 常见编译警告（当前存在，不影响运行）

| 警告 | 原因 | 处理建议 |
|---|---|---|
| NU1603 | csproj 指定 OpenCvSharp4 4.8.1.26，但源中只有 4.9.0.20240103，NuGet 自动升版 | 若想消除，把两个包版本改成 `4.9.0.20240103` 并重新还原 |
| NU1900 | 本机 NuGet 漏洞缓存目录 `D:\tang\donet_librarys\v3-chche\...` 无写权限 | 赋予该目录写权限或忽略（不影响编译） |
| CS8618 | `VideoProcessingViewModel._outputFolder` 在构造函数前被视为可能为 null | 可给字段初始化为空字符串，当前运行不受影响 |
| NETSDK1138 | .NET 6 已停止支持，使用新 SDK 构建 net6.0 时的 EOL 提示 | 升级 TargetFramework，或在 csproj 加 `<CheckEolTargetFramework>false</CheckEolTargetFramework>` |

## 7. 关键实现约定（便于二次开发）

- **输出不得等于输入**：`VideoJobService.EnsureOutputIsDistinct`（增强/裁剪/M3U8/音轨/GIF）以及 `ComposeAsync`、`ConcatAsync` 内的独立判断，避免覆盖源素材；
- **图像输出固定 PNG**：`ImageFileIO.WritePng`，Unicode 路径安全；
- **批量跳过已处理文件**：文件名以 `_processed` 结尾的输入会被跳过，防止重复处理；
- **语言资源**：`LocalizationManager`（位于 `FfmpegLocator.cs`）替换合并字典中含 `Strings.` 的项；新增文案需同时补 `Strings.zh-CN.xaml` 与 `Strings.en-US.xaml`；
- **去水印 ROI 坐标**：界面 Canvas 坐标经 `scale + 居中偏移` 换算成视频像素坐标，宽/高小于 4px 的区域被丢弃。
