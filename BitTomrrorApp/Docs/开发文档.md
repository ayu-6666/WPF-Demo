# BitTomrrorApp 软件开发文档

> 版本：1.1 ｜ 更新日期：2026-11-04 ｜ 适用模块：`WPF-Demo/BitTomrrorApp`

Windows 桌面多协议下载器，支持 **BT 种子/磁力链、HTTP(S) 直链、M3U8(HLS)、Telegram Bot 文件、FTP/FTPS** 五类资源的真实下载，全部进度、速度、校验数据均来自真实传输，无任何模拟进度。

---

## 1. 技术栈

| 组件 | 版本 | 用途 |
|---|---|---|
| .NET (net8.0-windows) | 8.0 | 运行时 |
| WPF + MaterialDesignThemes | 5.0.0 | UI 框架与控件样式 |
| CommunityToolkit.Mvvm | 8.2.2 | ObservableObject / MVVM |
| MonoTorrent | 3.0.2 | BT 协议（tracker/DHT/PEX/分片校验/做种） |
| FluentFTP | 55.1.0 | FTP/FTPS 客户端（被动模式、断点续传） |
| System.Security.Cryptography.ProtectedData | 8.0.0 | DPAPI 凭据加密 |

约束：不自写任何协议实现（BT tracker/DHT、FTP、HLS 解析基于标准库/成熟库）；Telegram 仅使用 Bot API（单文件 ≤20 MB，未集成 MTProto）。

```
├─ ViewModels/

├─ Views/
│  ├─ AddTaskWindow.xaml(.cs)        # 高级添加（5 个 Tab，自动回填设置中心凭据）

│  ├─ HttpDownloadService.cs         # HTTP 直链服务
│  ├─ BitTorrentDownloadService.cs   # BT 服务（MonoTorrent ClientEngine）
│  ├─ M3u8DownloadService.cs         # HLS 服务（解析/AES-128/分片/ffmpeg 合并）

```

分层规则：`ViewModel/View` 不直接触碰协议库；类型相关逻辑全部在各 `*DownloadService` 内实现，通过 `IDownloadService` 统一接入 `DownloadManager`；UI 状态更新统一走 `DownloadTask.Apply()`（投递到 UI `SynchronizationContext`）。

## 3. 核心机制

### 3.1 统一任务模型（DownloadTask）

- 类型枚举：`BitTorrent / Http / M3u8 / Telegram / Ftp`；状态枚举：`Waiting / Preparing / Downloading / Paused / Seeding / Completed / Error / Stopped`。
- 每类型特有配置字段（持久化到 tasks.json）：BT 限速/做种比例/做种时长、HTTP 连接数、M3U8 码率、TG token/file_id/chat/message、FTP host/port/user/pass/remote/TLS。
- 派生显示属性：`StateText / SizeText / DownloadedText / DownloadSpeedText / RemainingText / PeerText / ErrorText`；`RefreshDisplay()` 批量触发通知。
- 失败信息强制带错误码 + 明确原因（DNS/403/tracker 无响应/认证失败等），不允许笼统"下载失败"。

### 3.2 HTTP 引擎（HttpDownloadEngine，被 HTTP/Telegram 复用）

1. `Resolve`：GET 读取响应头得到总长度；无 `Accept-Ranges` 时补发 `Range: bytes=0-0` 探测续传能力。
2. 单连接：`Range: bytes=have-` 续传；多连接（用户可配 N）：按 Content-Length 均匀切片并发，分片级 `.part` 文件。
3. 重定向跟随；进度/速度来自真实字节计数。

### 3.3 BT（BitTorrentDownloadService / MonoTorrent）

- `ClientEngine`：DHT 启用、本地发现、fast-resume（`FastResumeMode.Accurate`）、DHT 缓存与磁力元数据缓存持久化。
- 种子：`Torrent.LoadAsync`；磁力：`MagnetLink.Parse`（无 tracker 时注入默认 tracker 列表，仍需 DHT/公网可达）。
- 状态机补齐（防止卡死/误报）：
  - 校验完成后 `HashCheckAsync(false)` 结束处于 Stopped：`manager.Complete` 为真 → 按做种配置转入 `Seeding` 或直接 `Completed`；
  - 首次进入 `Downloading` 时重置分片哈希计数（避免把启动空文件预校验记为"坏块"）；
  - `PieceHashed` 统计通过/失败分片，界面显示"N 个分片哈希有效"；失败分片由 MonoTorrent 自动重下。
- 事件级诊断：`ConnectionAttemptFailed(e.Reason)`、`PeerConnected`、`TorrentStateChanged(Error)` 均计入任务详情/失败原因。

### 3.4 M3U8（M3u8DownloadService）

- master/media 播放列表解析、按带宽选码率；支持 `EXT-X-KEY` AES-128 解密、`EXT-X-MAP` 初始化段（fMP4）。
- 分片并发下载、单分片重试与分片级续传（已完成分片跳过）。
- 合并：优先 ffmpeg（`-i playlist.m3u8 -c copy out.mp4` 转封装），失败自动回退内置 TS 拼接；ffmpeg 路径可配置并显示可用状态。

### 3.5 FTP（FtpDownloadService / FluentFTP）

- `AsyncFtpClient`，被动模式自动协商；可选显式 FTPS (TLS)。
- 断点续传：`.part` 文件 + `FtpLocalExists.Resume`（服务端 `REST` 偏移续传）。
- 凭据来源：设置中心默认配置或高级添加；错误密码等返回 `FTP_*` 错误码。

### 3.6 Telegram（TelegramDownloadService / Bot API）

- 流程：`getMe` 校验 token → `getFile`（支持 `file_id` 直取，或 `chat_id + message_id` 经 `getUpdates` 定位）→ 下载 `https://api.telegram.org/file/bot<token>/<file_path>`。
- 硬限制：Bot API 单文件 ≤20 MB（`getFile` 返回超限即报 `TG_FILE_TOO_LARGE`，不发起下载）；界面明确提示，未集成 MTProto。
- 测试钩子：环境变量 `TELEGRAM_API_BASE` 可覆盖 API 地址（默认官方），用于本地模拟 Bot API 验证。

### 3.7 个人设置中心与安全（SecureText / DownloadStore / SettingsWindow / LockWindow）

- **凭据加密**：FTP 密码、Telegram Token 以 DPAPI（`DataProtectionScope.CurrentUser`）加密后写入 settings.json，密文 `dpapi:v1:` 前缀；跨用户/跨机器无法解密，解密失败视为空。内存中的设置实例保持明文供界面回显。
- **启动密码**：PBKDF2-SHA256（10 万次迭代 + 16 字节随机盐）仅存哈希与盐（`LockPasswordHash/LockPasswordSalt`）；启用后 `App.OnStartup` 在主窗口前弹出 `LockWindow`，验证通过方可进入，取消则退出应用。修改/清除需先校验当前密码（`CryptographicOperations.FixedTimeEquals` 恒时比较）。
- **凭据清理**：设置中心提供"立即清除已保存的 FTP 密码与 Telegram Token"。
- 保存链路：设置窗口直接编辑 `DownloadManager.Instance.Settings` → `SaveSettingsNow()` → `DownloadStore.SaveSettings`（写副本加密，原子写）。
- 联动行为：
  - 高级添加各 Tab 自动回填已保存凭据（TG token/chat_id、FTP host/port/user/pass/remote/TLS）；
  - 主界面粘贴 `ftp://` 直链：已保存 FTP 凭据时自动用"URL 主机/路径 + 设置凭据"建任务，否则提示先去设置中心或高级添加。

### 3.8 数据文件与目录

| 位置 | 内容 |
|---|---|
| `%APPDATA%\BitTomrrorApp`（或 `BITTOMRROR_APP_DATA` 指定目录） | 数据根 |
| `settings.json` | 设置（敏感字段 DPAPI 密文） |
| `tasks.json` | 任务列表（含各类型配置），支持重启恢复 |
| `torrents/` | 种子副本、磁力元数据 |
| 任务临时目录 | `.part` 分片 / 分段文件，断点续传载体 |

## 4. 错误码规范

格式 `<类型>_<原因>`，界面显示"错误码：原因"。已覆盖（示例）：

| 错误码 | 含义 |
|---|---|
| `BT_TORRENT_INVALID` | 种子文件无法解析 |
| `BT_MAGNET_INVALID` | 磁力链接格式无效 |
| `BT_SOURCE_INVALID` | 输入既非种子也非磁力 |
| `BT_DUPLICATE` | 同一 info hash 重复添加 |
| `BT_ADD_FAILED` / `BT_RESUME_FAILED` / `BT_FAILED` | 引擎加入/恢复/运行失败（含原始消息） |
| `TG_TOKEN_MISSING` / `TG_INPUT_MISSING` | 未配置 Token / 未提供文件定位信息 |
| `TG_HTTP_401` | Token 无效（getMe 返回 Unauthorized） |
| `TG_FILE_TOO_LARGE` | Bot API 20 MB 上限 |
| `FTP_AUTH_FAILED` | FTP 认证失败 |
| `HTTP_*` / `M3U8_*` | DNS 解析失败、HTTP 状态码（403/404…）、播放列表/密钥错误等，均带具体原因 |

## 7. 已知限制

1. **公网 BT 依赖网络可达性**：tracker/DHT/peer 端口（TCP/UDP 出站）被网络策略限制时 peers 为 0；本地真实 peer 全流程已验证。磁力链接需公网 DHT 获取元数据。
2. **Telegram 仅 Bot API**：单文件 ≤20 MB；端到端真实账户验证需用户提供 Bot Token。
3. **FTPS**：显式 TLS（FluentFTP 能力范围），隐式 FTPS 未启用。
4. **HLS DRM**（SAMPLE-AES/加密密钥服务）不支持。

## 8. 开发约定

- 所有 UI 状态变更经 `task.Apply(...)`；后台线程禁止直接改绑定属性后不通知。
- 新增下载类型：实现 `IDownloadService` → `DownloadManager` 注册 → `DownloadTask` 增加配置字段与 `TypeText/PeerText` 分支 → `AddTaskWindow` 增加对应 Tab。
- 禁止伪造进度/速度/校验结果；任何"完成"必须来自真实字节与哈希校验。
