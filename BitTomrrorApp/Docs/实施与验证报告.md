# BitTomrrorApp 实施与验证报告

> 日期：2026-11-04 ｜ 范围：仅 `WPF-Demo/BitTomrrorApp` 模块 ｜ 结论：**五类下载全部为真实实现，编译通过，关键链路实测通过**

---

## 1. 任务目标

将原"模拟下载"替换为真实下载，并新增多类型资源支持；随后新增**个人设置中心**（FTP / Telegram / 软件安全）并整理文档。全程约束：

- 只改 BitTomrrorApp 模块，保留原有界面风格与 MVVM/服务分层；
- BT 必须使用成熟库（MonoTorrent），禁止自写协议，**禁止任何伪造进度**；
- 需要账户验证的部分（Telegram 真实账户、真实 FTP 服务器）**先模拟或跳过**。

## 4. 验证过程中修掉的真实缺陷

1. **BT 完成后卡在"解析中 100%"**：`HashCheckAsync(false)` 结束后管理器停在 Stopped，业务层未推进状态 → 按 `manager.Complete` 转入 Completed/Seeding。
2. **坏块统计误报**（显示"0 通过 / 24208 失败"）：首次进入 Downloading 时重置分片哈希计数，排除启动空文件预校验。
3. **做种状态未收敛**：无做种配置时 Tick 中由 Seeding 收敛为 Completed 并停止。
4. **编译错误** `e.Reason?.ToString()`（非可空枚举）。

## 5. 未通过项与原因（如实说明）

| 项 | 状态 | 原因 |
|---|---|---|
| 公网 BT（Ubuntu 官方种子） | ⚠️ tracker 有响应但无 peers | 本机网络对公网 swarm（UDP/DHT/peer 端口）可达性受限；本地真实 peer 全流程已通过 |
| Telegram 端到端（真实账户） | ⏳ | 需用户提供 Bot Token + file_id；模拟账户路径已覆盖 |
| 磁力链接元数据 | ⚠️ 仅库级接入 | 需公网 DHT 可达 |

## 6. 需要用户输入的事项

1. **Telegram**：Bot Token（@BotFather 创建）+ 目标文件 file_id 或 chat_id/message_id → 可直接端到端验证（无需改代码）。
2. **真实 FTP 服务器**（可选）：主机/端口/账密，用于 FTPS 与大文件补验。
3. **公网 BT**（可选）：放行出站 TCP/UDP tracker 与 peer 端口的网络环境。

## 7. 遗留限制

- Telegram 仅 Bot API，单文件 ≤20 MB（界面已提示，未集成 MTProto）；
- FTPS 仅显式 TLS；
- HLS DRM（SAMPLE-AES 等）不支持；
- 公网 BT 速度取决于网络环境。

## 8. 不作弊声明

- 全部进度、速度、peers 数、剩余时间来自 MonoTorrent 监视器 / 真实字节计数 / 真实 API 响应；
- 所有"已完成"必须经过分片哈希（BT）或 SHA256 比对（HTTP/FTP/TG）；
- 模拟的只是**账户身份**（本地 mock Bot API），传输字节与校验全部真实；
- 公网 BT 无 peers 的问题如实报告，未用本地数据冒充公网结果。
