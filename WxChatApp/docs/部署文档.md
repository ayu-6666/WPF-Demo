# WxChatApp 软件环境部署文档

> 面向部署/运维人员：从零搭建环境、编译、部署运行、配置与常见问题排查。

---

## 1. 环境要求

| 组件 | 要求 | 说明 |
|------|------|------|
| 操作系统 | Windows 10 1809+ / Windows 11 / Windows Server 2019+ | 客户端为 WPF，仅支持 Windows |
| .NET SDK | **.NET 8.0 SDK**（8.0.x） | 编译客户端与服务端均需要；只部署可用 Runtime |
| .NET Desktop Runtime | 8.0.x | 只运行客户端（WPF）的机器需要 |
| ASP.NET Core Runtime | 8.0.x | 只运行服务端的机器需要 |
| 端口 | TCP **5210**（可改） | 服务端监听端口，防火墙需放行 |
| 磁盘 | ≥ 200MB | 含 SQLite 数据库与上传的媒体文件 |
| 麦克风（可选） | 录音功能需要 | 仅发语音的客户端机器需要 |

SDK 下载：https://dotnet.microsoft.com/download/dotnet/8.0

检查安装：

```powershell
dotnet --info          # 确认 8.0.x SDK / Runtime 就位
```

## 2. 获取与编译

源码位于仓库 `WxChatApp/` 目录，采用多工程结构：客户端 `WxChatClientApp/WxChatApp.csproj`、服务端 `WxChatServer/WxChatServer.csproj`（模块根目录不再有 `.csproj` / `.sln`）。

```powershell
# 还原 + 编译服务端
dotnet build WxChatApp\WxChatServer\WxChatServer.csproj -c Debug

# 还原 + 编译客户端
dotnet build WxChatApp\WxChatClientApp\WxChatApp.csproj -c Debug

# 发布（正式部署建议 Release；服务端为自包含单文件，可脱离 .NET 运行时运行）
dotnet publish WxChatApp\WxChatServer\WxChatServer.csproj -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none -o publish\server
dotnet publish WxChatApp\WxChatClientApp\WxChatApp.csproj -c Release -o publish\client
```

> 客户端依赖 NuGet 包 `CommunityToolkit.Mvvm`、`NAudio`；服务端依赖 `Microsoft.Data.Sqlite`、`SignalR`。首次编译会自动还原。
> 服务端发布产物只有 `WxChatServer.exe`（约 94 MB，含 .NET 8 运行时与 SQLite 原生库）+ 可选的 `App_Data` 数据目录，**单独拷贝这一个 exe 即可运行，不要求目标机安装 .NET**。

## 3. 部署运行

### 3.1 服务端

1. 将 `publish\server` 复制到服务器（任意可写目录，如 `D:\WxChatServer`）；如只需单机运行，**直接拷贝 `WxChatServer.exe` 一个文件也可**（首次运行会在 exe 同目录自动创建 `App_Data`）。
2. 启动（任选其一）：

```powershell
# 双击 WxChatServer.exe，或在终端里
.\WxChatServer.exe
```

> 单文件版已内置 .NET 8 运行时，**不再需要 `dotnet WxChatServer.dll`**；双击后若窗口一闪而过，说明端口被占用或目录不可写，请在终端运行以查看报错（见 FAQ）。
> 如需把数据放到其它位置，启动前设置环境变量 `WXCHAT_DATA`（绝对路径），例如 `set WXCHAT_DATA=D:\WxChatServer\App_Data`。

3. 验证：浏览器访问 `http://<服务器IP>:5210/api/health`，返回 `{"ok":true,...}` 即正常。

4. 数据与文件位置（相对服务端运行目录）：

| 路径 | 内容 |
|------|------|
| `App_Data\wxchat.db` | SQLite 数据库（用户/消息/朋友圈等全部业务数据），**备份即复制此文件** |
| `App_Data\uploads\` | 聊天图片/语音/文件/朋友圈图片 |

5. 防火墙放行：

```powershell
New-NetFirewallRule -DisplayName "WxChatServer" -Direction Inbound -Protocol TCP -LocalPort 5210 -Action Allow
```

### 3.2 客户端

1. 将 `publish\client` 整个目录复制到使用者电脑（如 `C:\Tools\WxChatApp`）。
2. 双击 `WxChatApp.exe` 运行；可创建快捷方式。
3. 若服务端不在本机，**启动前**设置环境变量：

```powershell
# 当前会话
$env:WXCHAT_SERVER = "http://192.168.1.100:5210"
.\WxChatApp.exe

# 永久（用户级）
[Environment]::SetEnvironmentVariable("WXCHAT_SERVER", "http://192.168.1.100:5210", "User")
```

#### 登录页服务状态信号灯

登录窗口左下角有一个状态指示灯，用于快速判断「客户端连不上」是服务端问题还是网络/配置问题：

| 状态 | 含义 |
|------|------|
| 灰点「正在检测服务…」 | 首次检测尚未返回 |
| 绿点「服务正常」 | `GET {WXCHAT_SERVER}/api/health` 返回 2xx |
| 红点「服务不可用」 | 请求失败、超时（3 秒）或非 2xx |

- 刷新策略：进入登录页立即检测一次，之后每 5 秒自动检测；点击小圆点或文字可立即重新检测。
- 悬停指示灯可看到完整检测地址与最近一次检测时间。
- 该检测为匿名请求，不受登录状态影响；红灯持续出现时先按「常见问题」排查服务端与端口。

### 3.3 托管为 Windows 服务（可选，服务端常驻）

推荐用 [NSSM](https://nssm.cc/) 或 `sc.exe` 包装：

```powershell
nssm install WxChatServer D:\WxChatServer\WxChatServer.exe
nssm start WxChatServer
```

### 3.4 一键部署脚本 `scripts/deploy-server.bat`

脚本位于仓库 `WxChatApp\scripts\deploy-server.bat`，完成「发布 → 停旧进程 → 放行端口 → 启动 → 健康检查」全流程。

| 命令 | 作用 |
|------|------|
| `deploy-server.bat` | 使用默认端口 5210 发布并重启 |
| `deploy-server.bat 5230` | 指定监听端口 |
| `deploy-server.bat 5210 install-service` | 发布并注册为 Windows 服务（需管理员） |
| `deploy-server.bat status` | 查看端口监听、服务状态与健康检查结果 |
| `deploy-server.bat stop` | 停止服务端进程与服务 |

执行步骤与要点：

1. 校验 `dotnet` 命令与服务端项目文件是否存在；
2. **先 `taskkill` 停掉旧进程，再 publish**：服务端若从 `publish\server` 运行，exe 被占用会让 `dotnet publish` 长时间卡住；
3. `dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish\server`（发布前会清理旧的多文件产物，仅保留 `App_Data` 数据目录）；
4. `netsh advfirewall` 放行 TCP 端口（非管理员会提示手动放行，不中断脚本）；
5. 设置 `WXCHAT_PORT` / `WXCHAT_DATA` 后以最小化窗口启动 `publish\server\WxChatServer.exe`；
6. PowerShell 轮询 `/api/health`，最长 25 秒，输出「服务已就绪」或「未通过健康检查」。

注意事项：

- 数据目录默认为 `publish\server\App_Data`；若运行脚本前已存在 `WXCHAT_DATA` 环境变量，脚本沿用该值，可用于接管已有历史库。
- 脚本文件为 **UTF-8 无 BOM + CRLF 换行**。用只写 LF 的编辑器保存会导致 `cmd` 逐行解析错乱（如 `'1"=="" (' 不是内部或外部命令`）。
- 自动化/CI 场景可先设置 `set WXCHAT_NOPAUSE=1`，脚本将跳过所有 `pause`。
- 端口修改后记得同步客户端的 `WXCHAT_SERVER`。

## 4. 配置项

| 配置 | 位置 | 默认值 | 说明 |
|------|------|--------|------|
| 服务端地址 | 客户端环境变量 `WXCHAT_SERVER` | `http://127.0.0.1:5210` | 多机联调必改 |
| 监听地址/端口 | `WxChatServer/Program.cs`（`UseUrls` / launchSettings） | `0.0.0.0:5210` | 改后需重新编译或用 `--urls` 参数：`WxChatServer.exe --urls http://0.0.0.0:5210` |
| 上传大小上限 | `Program.cs` `/api/upload` | 20MB | 超限返回错误提示 |
| 上传扩展名黑名单 | `Program.cs` | .exe/.bat/.cmd/.com/.scr/.msi/.js/.vbs/.ps1/.sh | 按需调整 |
| 本机设置 | `%LOCALAPPDATA%\WxChatApp\settings.json` | - | 记住账号、通知开关等（不含密码） |
| 表情包目录 | `%LOCALAPPDATA%\WxChatApp\stickers\` | 内置 12 个 + 用户自定义 | 可直接放 jpg/png 进 user 目录 |
| 图片缓存 | `%LOCALAPPDATA%\WxChatApp\cache\` | 自动清理策略：无 | 过大可手动清空 |
| 语音播放缓存 | `%TEMP%\WxChatVoice\` | msg_*.wav | 可整目录删除，不影响功能 |

## 6. 常见问题（FAQ）

| 现象 | 原因 | 处理 |
|------|------|------|
| 登录页提示「无法连接服务器，请先启动 WxChatServer」 | 服务端未启动 / 端口不通 / `WXCHAT_SERVER` 配错 | 先访问 `/api/health` 排查；`Test-NetConnection <ip> -Port 5210` 测端口；核对环境变量 |
| 服务端启动报端口占用 | 5210 被旧进程占用 | `Get-NetTCPConnection -LocalPort 5210` 找到 PID → `taskkill /PID <pid> /F` |
| 双击 `WxChatServer.exe` 一闪而过 / 提示找不到 `WxChatServer.dll` | 用的是旧的多文件发布（exe 需与 dll、deps.json 同目录）；单独拷 exe 必然失败 | 改用自包含单文件产物：`publish\server\WxChatServer.exe`（本轮之后重新执行 `scripts\deploy-server.bat` 即可生成），单文件可单独拷贝运行 |
| 客户端启动后闪退 | 缺 .NET Desktop Runtime 8；或 `%LOCALAPPDATA%` 不可写 | 装齐 Runtime；检查目录权限 |
| 语音发不出去（提示太短/失败） | 按住 <1 秒；或麦克风被其它程序占用；或服务端为旧版本 | 按住 ≥1 秒；关闭占用麦克风的软件；确认服务端为含 `voice` 类型白名单的新构建 |
| 文件发送报「文件类型不允许」 | 上传黑名单拦截 | 服务端 `Program.cs` 调整黑名单后重启 |
| 发文件/语音成功但对方看到的是文本 | 服务端版本过旧（Hub 白名单只放行 image/text） | 升级服务端到含 `type is "image" or "voice" or "file"` 的构建 |
| 图片/表情包显示空白 | 缓存目录被清且服务端媒体文件被删 | 历史消息无法再取图；新消息正常。勿删 `App_Data\uploads` |
| 多人同时在线卡顿 | 单机 SQLite + 内存 Presence 的设计上限（局域网小团队规模） | 大规模需换 PostgreSQL/Redis 与分布式在线状态 |
| 数据库损坏 | 强杀进程极端情况下 | 从备份恢复 `wxchat.db`；WAL 模式下正常停止进程即可 |

## 7. 升级与回滚

1. **升级前备份**：停止服务端进程，复制 `App_Data\wxchat.db`（含 -wal/-shm 一并复制）。
2. 覆盖部署新 `publish\server` 产物，启动即可；建表语句幂等（`CREATE TABLE IF NOT EXISTS`），旧库自动沿用。
3. 客户端升级只需覆盖目录；用户数据（表情包/设置）在 `%LOCALAPPDATA%` 不受影响。
4. 回滚：还原备份 db 文件 + 换回旧版本程序目录。

## 8. 安全建议（生产环境）

- 服务端目前为 HTTP 明文 + 固定端口，生产环境请置于 HTTPS 反向代理（Nginx/IIS/Caddy）之后，客户端 `WXCHAT_SERVER` 使用 https 地址。
- Token 为明文 Bearer，建议叠加传输加密；`sessions` 表可定期清理过期记录。
- `/api/upload` 建议增加：按用户限流、文件类型魔数校验、上传目录与站点隔离（当前已做扩展名黑名单 + 大小限制）。
- SQLite 建议每日计划任务备份 `wxchat.db`。

## 附录 A. 第二轮变更部署注意事项（2026-11-04）

### 数据库自动迁移

服务端 `Db.Init()` 已改为幂等建表 + 安全 `ALTER TABLE`。**覆盖部署新版本服务端后，旧数据库首次启动会自动补列/建新表**，无需手动迁移脚本：

- `ALTER TABLE users ADD COLUMN avatar TEXT NOT NULL DEFAULT ''`
- `ALTER TABLE friends ADD COLUMN tag TEXT NOT NULL DEFAULT ''`
- `CREATE TABLE favorites (...)`

部署顺序不变：**先停旧服务端 → 备份 `App_Data/wxchat.db`（含 -wal/-shm）→ 覆盖新产物 → 启动新服务端 → 看启动日志无异常**。

### 新增外部端口依赖

- 无。全部新增 REST/SignalR 路由仍在同一端口 5210 下。
- 客户端如需访问 API（头像上传/消息删除/收藏/搜索）沿用原有 bearer token 鉴权。

### 新增 REST 路由清单（给运维看）

| 方法 | 路由 | 鉴权 | 说明 |
|------|------|------|------|
| PUT | `/api/me` | ✓ | 新增可选字段 `avatarUrl` |
| GET | `/api/users/{id}` | ✓ | 用户详情（含 isFriend/tag） |
| PUT | `/api/friends/{friendId}/tag` | ✓ | 好友标签 |
| DELETE | `/api/messages/{id}` | ✓ | 仅发送者本人可删（服务端校验） |
| GET | `/api/messages/search?q=&limit=` | ✓ | 站内文本搜索 |
| GET | `/api/favorites` | ✓ | 我的收藏列表 |
| POST | `/api/favorites` | ✓ | 收藏消息 |
| DELETE | `/api/favorites/{id}` | ✓ | 取消收藏 |

## 附录 B. 第三轮变更部署注意事项（2026-11-05）

### 数据库

新版本启动时仍为幂等迁移，额外创建两张表（旧库自动补齐）：

- `CREATE TABLE official_accounts (...)` — 公众号信息
- `CREATE TABLE official_messages (...)` — 公众号图文
- 首次启动时写入 3 个内置公众号、6 篇示例图文（仅当表为空时执行，不会覆盖已有数据）

无字段变更，无需手工迁移。备份策略不变：复制 `App_Data` 目录。

### 新增 REST 路由

| 方法 | 路由 | 鉴权 | 说明 |
|------|------|------|------|
| GET | `/api/moments/search?q=&limit=` | ✓ | 朋友圈搜索（自己 + 好友可见） |
| GET | `/api/official/accounts` | ✓ | 公众号列表 |
| GET | `/api/official/messages?accountId=&limit=` | ✓ | 公众号图文列表 |

### 新增 SignalR 方法与事件（通话信令）

| 方向 | 名称 | 参数/说明 |
|------|------|-----------|
| 客户端 → 服务端 | `StartCall` | `(convType, targetId, kind)` → 返回 `callId`（仅单聊） |
| 客户端 → 服务端 | `RespondCall` | `(callId, accepted)` |
| 客户端 → 服务端 | `EndCall` | `(callId)` |
| 服务端 → 被叫 | `incomingCall` | `(callId, fromId, fromName, kind)` |
| 服务端 → 主叫 | `callResponse` | `(callId, accepted, byName)` |
| 服务端 → 对端 | `callEnded` | `(callId, fromId)` |

### 能力说明（告知运维/测试）

- 通话功能仅传输信令，**不传输真实音视频流**；客户端窗口底部有明确提示。
- 视频号、扫一扫、小程序仍为占位入口，点击提示"暂未实现"。
- `merge` 消息类型内容为 JSON，单条上限 8000 字符。

### 部署验证清单

1. 启动服务端，日志显示监听 5210，无迁移异常。
2. `GET /api/official/accounts`（带 Bearer）返回 3 个公众号。
3. 两个客户端登录 `wxtest_a` / `wxtest_b`，验证：多选 → 合并转发、发现页搜一搜（好友/消息/朋友圈）、公众号图文打开、语音/视频通话呼入与接听。
